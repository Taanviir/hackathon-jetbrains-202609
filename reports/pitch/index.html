One plugin, two connected workspaces: find the files a task needs, then review a coding model's proposed changes before applying them.
The problem

An agent's first minutes are a scavenger hunt

grep "retry"read Client.ktgrep "backoff" read Config.ktglob **/*Retry*read RetryPolicy.kt grep "delay"read ClientTest.ktedit

Each hop is a full LLM round-trip: tokens in, tokens out, seconds gone. On a 2,000-file project the agent reads files one at a time to find the three that matter.

Real Koog tasks: Claude Code averaged 13 turns per task.

The IDE already knows every file. The agent is re-discovering the project through a keyhole, one tool call at a time.
The insight

Use a model that decides, not one that writes

Jev

Judges, never writes

TypeSafe's System One model answers typed questions with calibrated probabilities. No text generation, so it's fast.

Batching

60 files per call

One call asks "does this task need file f07?" about 60 files at once, and many calls run in parallel.

Measured pack

About $0.03

One warm Jev pack across 2,206 Koog files in the IDE. API fee only.

Let Jev do the looking. Leave the writing to the LLM.

An LLM is the wrong tool for asking the same question 2,000 times. Jev is built for exactly that.
How it works

Find the files worth reading before the agent starts

01

Sketch

Every file becomes a ~300-token outline: path, declarations, doc lines.

2,206 files · 1.4 s
02

Pass 1

Jev scores all sketches. BM25 keyword search ranks full text alongside.

60 files / call
03

Pass 2

The top 60 of each go back to Jev with their full source.

6 files / call
04

Fuse

Jev and BM25 count equally. Weight picked on dev tasks only.

equal weight
05

Compare

One Jev choice over the top 10: which file must be edited?

+0.4 s

Result: the top 10–20 files, tests flagged, with roles like edit, test and example.

Jev alone on sketches actually loses to keyword search. The win comes from re-ranking on full source and fusing with BM25. We measured that, which is why the pipeline looks like this.

Choose how context is found

Three modes. One developer workflow.

Jev · cloud

Deep ranking

Batch full-project sketches, re-rank full source and combine with keyword evidence.

Laya · local

Your model, your machine

Use a local server with its own model, endpoint and context-budget settings.

Keywords · local

Zero API calls

Search the full eligible source corpus with BM25. No model or key required.

Switch providers in the same IntelliJev window. Jev and Laya keep independent settings.

The 0.69 recall@10 and 4.4 s figures are Jev measurements. Laya and keywords were evaluated separately.
This is one product choice inside one plugin, not three plugins or a single lowest-common-denominator configuration.
Live demo

Watch the agent skip the hunt

  1. Open IntelliJev in IntelliJ IDEA. Choose Find context and select a provider.
  2. Enter a Koog task, then pack context. Show the ranked files and select the ones the change needs.
  3. Press Review changes. The same task and selected context move to the review workspace.
  4. Request a proposal, inspect the diff and apply a selected change only after approval.
For a reliable live demo, use a configured provider and coding model or show a recorded run of the same workflow. The agent hook is an additional integration, not a required step in this IDE flow.
Next · product direction

The IDE should know when to think harder

Route the task. Use the right model for the work, instead of sending every request to a frontier model.

Recall what matters. Bring forward relevant history without carrying the entire conversation.

Find the right skill. Surface the tool or workflow the task calls for.

IntelliJev today: context and reviewed edits. These are the next capabilities we envision.
The same small, structured decision that helps find files could later help choose models, history and skills. These are product directions, not benchmarked features in the current plugin.
